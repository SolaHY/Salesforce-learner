Salesforce Certified Administrator ／ 設定とセットアップ・セキュリティ

ログインとアクセス制御／通す条件と弾く条件

「ログインできない」の原因は、たいてい設定場所が違うだけの似た機能が並んでいることにあります。 このページは どこで設定するか（プロファイル単位か、組織全体か） と 引っかかったらどうなるか（拒否されるのか、本人確認で済むのか） の 2 軸で全体を並べ直したものです。

  • 紫＝プロファイル単位の設定
  • 藍緑＝組織全体の設定
  • 緑＝そのまま通す
  • 琥珀＝追加の本人確認が要る
  • 赤＝拒否・ブロック
01

全体像 — ログイン 1 回で通過する 7 つの関門

ユーザがログインボタンを押してから画面が開くまでに、7 つのチェックが順番に走ります。 重要なのは、それぞれ設定する場所が違うことと、失敗したときの結果が「拒否」と「追加の本人確認」の 2 種類あることです。 トラブルの切り分けは、この順番のどこで止まったかを特定する作業になります。

02

パスワードポリシー — 組織全体とプロファイルの二層構造

パスワードポリシーは ［設定］→「セキュリティ」→「パスワードポリシー」 で組織全体の既定値を決め、 プロファイルごとに個別の値で上書きできます。厳しくしたい部門だけ別プロファイルにする、という運用がとれるのはこのためです。

パスワードの有効期限 30 / 60 / 90 / 180 / 365 日、期限なし90日 期限が切れると次回ログイン時に強制的に再設定させられる。「パスワード無期限」権限を持つユーザは対象外。
パスワード履歴の保存 1〜24 個、保存しない3個 直近の何個分を再利用禁止にするか。有効期限を設定している場合は「保存しない」を選べない。

03

IP アドレスの 2 つの顔 — 「弾く制限」と「確かめない範囲」

このドメインで最も間違えやすいのがここです。IP に関する設定は名前が似た 2 つがあり、目的も設定場所も結果もまったく違います。 プロファイルの「ログイン IP アドレスの制限」は範囲外を拒否する門番、 組織全体の「信頼済み IP 範囲」は本人確認を省略してよい相手のリストです。

表 2 ／ ログイン IP アドレスの制限と信頼済み IP 範囲の比較
観点 ログイン IP アドレスの制限 信頼済み IP 範囲（ネットワークアクセス）
設定場所［設定］→ プロファイル →「ログイン IP アドレスの制限」［設定］→「セキュリティ」→「ネットワークアクセス」
適用範囲そのプロファイルのユーザだけ組織のすべてのユーザ
目的許可した場所以外からのログインをさせない信頼できる場所からのログインで本人確認を省く
範囲内のときログインできる確認コードなしでログインできる
範囲外のときログインできない（拒否）ログインはできる。ただしメール等の確認コードが必要
API・データローダ範囲外なら同じく拒否される範囲内ならセキュリティトークンが不要になる
未設定のときIP による制限なし（どこからでも可）すべての接続元が「信頼済みでない」扱い
典型的な使い方本社オフィスからのみ操作させたい経理担当プロファイル社内ネットワークからは毎回の確認コードを省きたい

設定するときの手順

  1. 接続元の IP アドレスを確認する社内の固定グローバル IP を把握する。ログイン履歴の「送信元 IP アドレス」列からも実際の値を確認できる。
  2. プロファイルに範囲を登録する［設定］→ プロファイル → 対象プロファイル →「ログイン IP アドレスの制限」で開始 IP と終了 IP を入力。IPv4 / IPv6 に対応し、複数行を登録できる。
  3. 自分が締め出されないか確かめるシステム管理者プロファイルに厳しい制限をかけると、管理者自身が入れなくなる。作業前に別の管理者ユーザを用意しておくのが定石。
  4. 信頼済み IP 範囲は別途登録する［設定］→「ネットワークアクセス」に登録すると、その範囲からは確認コードとセキュリティトークンが不要になる。プロファイル側の制限とは独立した設定。
締め出しに注意 プロファイルの IP 制限は、そのプロファイルのユーザ全員に即時に効きます。自分自身のプロファイルに設定して範囲を間違えると、 誰もログインできない組織ができあがります。設定前に、制限のかかっていない管理者ユーザを 1 つ確保しておいてください。
04

ログイン時間制限 — 曜日と時間帯で絞る

プロファイル単位で「この曜日のこの時間しかログインさせない」を設定できます。 アルバイトや業務委託のアカウントを業務時間内に限定する、といった用途です。

設定場所 PROFILE

［設定］→ プロファイル →「ログイン時間」。曜日ごとに開始時刻と終了時刻を指定します。何も設定しなければ制限なしです。

判定に使うタイムゾーン TIMEZONE

ユーザ個人のタイムゾーンではなく組織の既定のタイムゾーンで判定されます。海外拠点のユーザがいる組織では特に間違えやすい点です。

時間外になったとき SESSION

ログイン中に終了時刻を迎えると、そのまま操作を続けることはできなくなります。表示中のページは見えていても、保存や画面遷移をしようとするとログイン画面に戻されます。

IP 制限との組み合わせ COMBINE

ログイン時間と IP 制限はどちらもプロファイル単位で、両方を満たさないとログインできません。「社内から、かつ営業時間内だけ」という絞り込みができます。

05

本人確認・MFA・セキュリティトークン

「追加でもう一段確かめる」仕組みは 3 つあり、目的が異なります。 ID 確認は見慣れない接続元への確認、MFAは常時要求される 2 つ目の要素、 セキュリティトークンは画面を持たない API 接続のための代替手段です。

ID 確認（デバイスの有効化） VERIFY

信頼済み IP 範囲外から、かつ見慣れないブラウザやデバイスでログインすると、メールなどに確認コードが送られます。一度確認したブラウザは記憶されます。

多要素認証（MFA） MFA

パスワードに加えて、Salesforce Authenticator・認証アプリ（TOTP）・セキュリティキーなどの 2 つ目の要素を必須にします。現在は全ユーザで必須の扱いです。

セキュリティトークン API

API やデータローダなど画面を持たない接続で、確認コードの代わりに使う 24 文字の文字列。パスワードの末尾に連結して送ります。

MFA と ID 確認の違い ID 確認は「いつもと違う場所・端末からのログイン」に反応する条件付きの確認で、信頼済み IP 範囲内なら省略されます。 一方 MFA は条件に関わらず毎回要求される 2 つ目の要素です。「社内からなら MFA も省略されるのか」という問いの答えはいいえです。
06

セッションの設定 — ログインしたあとの寿命

ログインに成功したあとの挙動は ［設定］→「セキュリティ」→「セッションの設定」 で決まります。 組織全体の既定値に対して、プロファイル側でセッションタイムアウトを個別に上書きできます。

表 3 ／ セッションの設定でよく問われる項目
設定項目 値・挙動
セッションのタイムアウト値15 分〜24 時間（既定 2 時間）。無操作がこの時間続くと自動的にログアウトされる。プロファイル単位でも設定できる。
タイムアウト警告のポップアップ切断の直前に警告を表示し、その場でセッションを延長させる。無効にすると予告なくログアウトされる。
セッションを発信元 IP アドレスにロックログイン時と異なる IP からのアクセスでセッションを無効にする。モバイル回線の切り替えなどで頻繁に切れることがあるため注意。
安全な接続（HTTPS）が必要すべての通信を HTTPS に強制する。既定で有効で、通常は無効にしない。
ログイン IP 範囲の適用時に強制プロファイルの IP 制限を、ログイン時だけでなくセッション中も継続的に評価する設定。
タイムアウトと時間制限の違い セッションタイムアウトは無操作の長さで切れるもの、ログイン時間制限は時計の時刻で切れるものです。 「操作していたのに 18 時ちょうどで切れた」ならログイン時間制限、「席を外していたら切れた」ならセッションタイムアウトです。
07

運用と切り分け — 入れないと言われたら

調査と復旧に使う道具

ログイン履歴 LOG

［設定］→「ログイン履歴」で直近 6 か月・最大 2 万件を確認できます。日時・送信元 IP・ログイン種別・状況（成功／失敗理由）が並び、CSV でダウンロードもできます。原因の特定はまずここから。

ユーザとしてログイン LOGIN AS

管理者がユーザの画面をそのまま再現して確認できます。組織の設定で「管理者がすべてのユーザとしてログインできる」を有効にするか、ユーザ側から期限付きでログインアクセスを許可してもらいます。

凍結と無効化 USER

凍結は一時的にログインを止めるだけでライセンスは解放されません。無効化はライセンスを解放しますが、承認プロセスなどに関わっていると実行できない場合があります。ユーザの削除はできません。

委任管理者 DELEGATE

システム管理者権限を丸ごと渡さずに、「特定プロファイルのユーザ作成とパスワードリセットだけ」を部門担当に任せられます。ロック解除やリセットの依頼を分散させたいときに使います。

よくある取り違え

  • 信頼済み IP 範囲に追加すれば IP 制限を回避できる、と考えてしまう（できません。別の設定です）
  • ログイン時間の判定をユーザ個人のタイムゾーンだと思い込む（組織の既定タイムゾーンです）
  • ロック解除とパスワードリセットを同じ操作だと思う（ロック解除はパスワードを変えません）
  • MFA が信頼済み IP 範囲内で省略されると考える（省略されるのは ID 確認のほうです）
  • セッションタイムアウトとログイン時間制限を混同する（無操作か、時刻かの違いです）
  • 権限セットでログイン IP 範囲を設定しようとする（IP 制限とログイン時間はプロファイル側の設定です）
08

試験ポイントの総ざらい

設定場所と「拒否か確認か」の区別がそのまま出題されます。太字部分が答えになりやすい箇所です。

  1. 01プロファイルのログイン IP アドレスの制限は、範囲外を完全に拒否する。
  2. 02組織全体の信頼済み IP 範囲は、範囲内で本人確認を省略する設定。範囲外でもログイン自体はできる。
  3. 03両者が競合したときはプロファイルの制限が優先し、信頼済み IP では救済されない。
  4. 04信頼済み IP 範囲は ［設定］→「ネットワークアクセス」、IP 制限はプロファイルで設定する。
  5. 05ログイン時間制限はプロファイル単位で、判定は組織の既定タイムゾーン。
  6. 06ログイン中に時間外になると、それ以上の操作ができなくなる。
  7. 07パスワードポリシーは組織全体とプロファイルの両方で設定でき、プロファイル側が優先される。
  8. 08パスワードの有効期限の既定は 90 日、最小文字数の既定は 8 文字、履歴の既定は 3 個。
  9. 09ロックアウトの有効期間には 15 / 30 / 60 分と管理者が解除するまでがある。
  10. 10ロック解除とパスワードリセットは別の操作。ロック解除ではパスワードは変わらない。
  11. 11「パスワード無期限」権限を持つユーザは有効期限の対象外になる。
  12. 12セキュリティトークンは API・データローダなど画面を持たない接続で使い、パスワードの末尾に連結する。
  13. 13信頼済み IP 範囲内からの接続ではセキュリティトークンが不要になる。
  14. 14トークンはパスワードを変更するたびに再発行され、古いトークンは使えなくなる。
  15. 15ID 確認は見慣れない接続元・端末で発生する条件付きの確認、MFA は毎回必須の 2 つ目の要素。
  16. 16セッションのタイムアウト値は 15 分〜24 時間（既定 2 時間）で、プロファイル単位でも設定できる。
  17. 17ログイン履歴では直近 6 か月・最大 2 万件を確認でき、CSV でダウンロードできる。
  18. 18ユーザは削除できない。凍結はライセンスを解放せず、無効化は解放する。
  19. 19管理者が代理でログインするには「ユーザとしてログイン」を使い、ユーザ側のログインアクセス許可が必要な場合がある。
  20. 20IP 制限とログイン時間は権限セットでは設定できず、プロファイル側の設定である。
